## Analytic and tessellated formats

Strict BRep v2 solids expose export directly on `AnalyticSolid` and the public analytic wrappers:

- `exportStep("metre" | "millimetre")` retains analytic geometry and topology.
- `exportIfc()` writes one analytic IFC4 product.
- `prepareIfcExchange()` returns Rust-prepared geometry for semantic IFC assembly.
- `exportStl(deflection)` creates a bounded transient triangle representation.
- `projectTo2DLines(camera, hlr)` projects analytic edges and classifications.

STEP and IFC read the BRep. STL reads a tessellation generated from the BRep at the requested
deflection. None of these paths rebuilds authority from the Three.js `BufferGeometry`.

```ts
const step = solid.exportStep("metre");
const ifc = solid.exportIfc();
const exchange = solid.prepareIfcExchange();
const stl = solid.exportStl(0.005);
```

## Placement and units

Authored dimensions are metres. Export applies the complete Three.js world placement once and
supports only positive uniform scale, which preserves the analytic surface families. STEP can emit
metres or millimetres. Prepared IFC bodies are world-space, Z-up, and metres so a downstream
assembler must not transform them again.

## Errors and budgets

Exchange and tessellation have separate error budgets. An invalid model, unsupported placement,
unrepresentable entity, exhausted resource limit, or unattainable Float32 STL tolerance produces a
structured error. Export never substitutes a viewport mesh or silently lowers the requested
quality.

## Scene workflows

[`WorldGraph`](/api/scene/scene-management) is the kernel's single scene. Its `exportStl`,
`exportStep`, and `exportIfc` write world-placed schema-v1 bodies and refuse analytic definitions;
export analytic solids through their own STEP/STL/IFC methods. For semantic multi-element
IFC, collect `prepareIfcExchange()` bodies under schema `"2.0"`; OpenPlans keeps multiple bodies of
one authored element in one `FREEFORM_ANALYTIC.geometries` array.

## Runtime differences

Browser/WASM exports return in-memory strings or bytes. Applications create a `Blob`, upload the
data, or persist it themselves. Native-only PDF and file-writing helpers are separate APIs.
